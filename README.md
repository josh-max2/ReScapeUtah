# datamaker dashboard — Vercel mirror

Read-only static mirror of the local datamaker analytics dashboard.

- **Live site:** deployed via Vercel from this repo's `main` branch.
- **Source server:** runs locally on the datamaker machine
  (`analysis/dashboard.py`, port 8765). Vercel never scrapes anything;
  it just serves the latest snapshot.
- **Refresh cadence:** the page auto-refreshes every hour via
  `<meta http-equiv="refresh">`. The data behind it updates whenever
  the local exporter pushes a new snapshot (hourly via Windows Task
  Scheduler, or manually via `python export_dashboard.py` from the
  datamaker repo).

## Files

| File | Source | Purpose |
|---|---|---|
| `index.html` | `analysis/dashboard.py:HTML`, transformed | The dashboard UI (Chart.js from CDN) |
| `data.json` | `compute_dashboard()` | Default payload (30d trend) |
| `data_7d.json`, `data_14d.json`, `data_30d.json`, `data_all.json` | same, per range | Range-toggle payloads |
| `vercel.json` | hand-written | Static-only deploy hints |

All files are regenerated by `export_dashboard.py` in the datamaker
repo. **Don't edit by hand** — your changes will be overwritten on the
next snapshot push.

## Updating manually

```powershell
cd C:\Users\joshs\Desktop\datamaker
"C:\AI\venv\Scripts\python.exe" export_dashboard.py
```

That runs `pull_tt_views.py` + `pull_yt_views.py` + `build_db.py`,
regenerates this repo's snapshot files, and pushes. Vercel
auto-redeploys on push (~30s).

## Skipping the pulls / push

```powershell
# regenerate from current local DB only (no scraping, no push)
python export_dashboard.py --once

# scrape but don't push
python export_dashboard.py --no-push
```
